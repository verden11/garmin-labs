# Connect IQ glances on watch-apps: pitfalls and field evidence (as of 2026-09-26)

Scope: adding `getGlanceView()` to an existing paid watch-app (HeroSet, `type="watch-app"`, `minApiLevel="3.4.0"`, 80 products, live at $1.99). Method note: most primary evidence is (a) the local SDK 9.2.0 docs (generated 2026-06-09; cited as `SDK doc: <file>`) and (b) Garmin Connect IQ developer-forum threads. Forum summaries below were extracted by a fetch tool that paraphrases; relative dates ("over 4 years ago") are as printed on the page and are approximate. Nothing here was run on a device.

Local-repo facts used for inferences (read from the repo, not the web):
- `HeroSet/source/app/HeroSetApp.mc`: `initialize()` builds `HeroSetStore` and `HeroSetSyncCoordinator`; `onStart()` calls `_store.ensureCurrentDay()` and `HeroSetComplicationPublisher.publish(_store)`; no `getGlanceView`, no `(:glance)` anywhere in `source/`.
- `HeroSet/manifest-store.xml`: permissions `ComplicationPublisher` and `Sensor`; 80 products identical to the dev manifest; `Fit`/`FitContributor` are not in the store build.
- `HeroSet/docs/decisions.md` ADR-046/047: the 1.0.0 crash was a `Watchdog Tripped Error - Code Executed Too Long` on a real FR965 (firmware 29.05, CIQ 6.0.2) in a save callback, found only on device; simulator number (55 ms) was wrong by ~3x. Same "simulator is not proof" lesson applies to glances (see Q1).

## Q1. Common failures: memory, scope/annotation crashes, blank/stale, missing glance, device quirks

### Takeaway
The dominant real-world failures are (1) glance code path exceeding the glance memory cap (32 KB on CIQ 3.x-era watches, 64 KB on the newer ones per the local device reference), producing a silent restart loop or crash with no stack trace; (2) glance code touching anything not `(:glance)`-scoped (classes, `Rez` resources, class-level `var` initialisers), which surfaces as "Illegal Access (Out of Bounds)" / Symbol-not-found style errors that crash before `onUpdate`; and (3) a glance simply not appearing (not overriding `getGlanceView()` on CIQ 4+, or a device/SDK regression). Simulator success is repeatedly reported as not predictive of device behaviour.

### Cited Findings

**Memory**
- Glances started from the glance list run in "Glance mode with limited memory allocated (32KB for most devices)"; `:glance` annotation selects which modules/classes load, like background services. Live-update devices keep the app alive; low-memory devices ("non-music wearables") launch the app only when the glance is shown and at least 30 s since the last update, running a full lifecycle (`onStart`, `getGlanceView`, `onLayout/onShow/onUpdate/onHide`, `onStop`) and cache what was drawn to the filesystem. Update rate should stay under 1 Hz. — SDK doc: `doc/docs/Core_Topics/Glances.html` (SDK 9.2.0, 2026)
- Per-device Glance memory limits in the SDK 9.2.0 Device Reference (I extracted these for the 80 products in HeroSet's manifest): **53 products = 65,536 B, note "Build as Watch App or Widget"; 17 products = 32,768 B, note "Build as Widget"** (fenix6, fenix6s, fenix6pro, fenix6spro, fenix6xpro, all 8 marq gen-1 products, descentmk2, descentmk2s, fr945lte, enduro). The remaining 10 manifest products have no page in the doc HTML but do have installed device files: **all 10 (fenix9 x7, fr170, fr170m, fr70) are 65,536 B** — from `~/Library/Application Support/Garmin/ConnectIQ/Devices/<id>/compiler.json` (`appTypes[type=glance].memoryLimit`). Across all 80 manifest products the device files give **63 at 65,536 B and 17 at 32,768 B**. — SDK doc: `doc/docs/Device_Reference/<product>.html`; local device files (`compiler.json`), SDK 9.2.0 era (2026)
- The 17 32 KB products are exactly the ones whose Device Reference glance note says "Build as Widget", i.e. the documented way to get a glance there is a widget-type build, not a watch-app. Same pages list their Watch App memory as 131,072 (fenix6/6S/enduro) or 1,310,720 (others). — SDK doc: same files
- Old but still the best on-device memory anecdote: adding a glance to a fēnix 6 app put the watch into a restart loop with no crash log; simulator was fine; app used 40–43 KB vs. "max is 32kb (in reality, 28kb)". Fix was trimming and `:glance` annotation. — [First widget with glance view - reset loop, Garmin forum, ~2019](https://forums.garmin.com/developer/connect-iq/f/discussion/192533/first-widget-with-glance-view---reset-loop)
- "The realistic limit is about 28k rather than the advertised 32k" and a memory spike occurs in `onBackgroundData` when old and new data coexist — search-result paraphrase of forum threads; I did not open the underlying post. — [News for Widget Glances!](https://forums.garmin.com/developer/connect-iq/f/discussion/213297/news-for-widget-glances) (secondary; treat as unverified detail)
- Garmin's own 2019 launch post: 32 KB glance maximum; a developer hit 29.8 KB peak on fēnix 6X, cut to 22.4 KB by restricting palette on a BufferedBitmap; glance canvases 151x63 (6S), 171x63 (6), 191x63 (6X) px. — [Widget Glances - A New Way to Present Your Data, Garmin forum news, 2019-10-30](https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/widget-glances---a-new-way-to-present-your-data)
- `AppBase` is always loaded in glance/background contexts (jim_m_58, forum), so anything `initialize()` constructs counts against the glance budget; `:glance` annotation does not shrink memory by itself, you must avoid instantiating heavy classes (deferred loading); and "`:glance` annotated code is NOT excluded from devices that do not support it at build time" (2019-era statement by a forum user, not verified against current compiler). — [Memory usage by "Code" in Glance View, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/195448/memory-usage-by-code-in-glance-view); [Glance Views out of memory, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/210767/glance-views-out-of-memory)
- Compiler only warns, not errors, when an app exceeds the glance memory limit (change dated CIQ 4.0.0). — SDK doc: `doc/docs/Readme/History.html`, v4.0.0 notes
- Storage/JSON in a glance: a 3.5 kB JSON became ~12 kB as a Dictionary and needed ~24 kB more while storing (~36 kB peak); the developer abandoned `Storage` in the glance "due to unpredictable interactions with competing applications". Storage docs conflict (8 KB per key vs 32 KB per value). — [Memory Requirements when Storing JSON from Glance, forum thread 412304, 2024-2025](https://forums.garmin.com/developer/connect-iq/f/discussion/412304/memory-requirements-when-storing-json-from-glance/1936906) (paraphrase; the "competing applications" cause is the poster's own, not confirmed by Garmin)

**Scope / annotation crashes**
- "Illegal Access (Out of Bounds)" on enabling glance mode on a fēnix 6 (worked on fēnix 5 and with glance off); cause: `class Foo { var bar = Rez.Drawables.baz; }` — a resource reference at class-var initialisation with resources not scoped for glance; stack trace pointed at an unrelated line. Another poster: "strange errors when glance code calls something which is not annotated for inclusion in a glance". — [GlanceMode causing Error: Illegal Access (Out of Bounds), forum](https://forums.garmin.com/developer/connect-iq/f/discussion/228440/glancemode-causing-error-illegal-access-out-of-bounds)
- Glance crashes reported as occurring before `GlanceView.onUpdate`, with no stack trace (search-result paraphrase). — [forum search results, e.g. Code crash only when type = widget](https://forums.garmin.com/developer/connect-iq/i/bug-reports/code-crash-only-when-type-widget) (not opened; unverified)
- Resources need `scope="glance"` (also `background`, `foreground`) to be reachable from the glance process. — [Glance Views out of memory, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/210767/glance-views-out-of-memory); SDK History v2.x: 'Add a "scope" attribute support for all resources to allow access for background and glance processes' (`History.html`)
- Compiler/type-checker history relevant to scope: "Apply scope checking for the background and glance portions of an app when the entire app is loaded into these processes" (v6.3.0, 2023-08-30 per the forum announcement); "Fix issue where an app didn't show up in the glance list if the entry point was in a module" (v6.2.0); "Improve code generation when `(:glance)` is used without implementing `getGlanceView`" and "Fix an issue where the compiler would error when background or glance resources were used in barrel code" (v9.2.0). — [Connect IQ 6.3.0 SDK Release](https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/connect-iq-6-3-0-sdk-release); SDK doc: `History.html`
- Return value: one forum answer says `getGlanceView()` should return only the view, not view+delegate, and that returning both "can cause crashes"; a different thread's fix was the opposite (associating the delegate so callbacks fire). Local API docs say it returns `[GlanceView]` or `[GlanceView, GlanceViewDelegate]` or null, and `onGlanceEvent` is "none for now". **Conflict, unresolved**: [Glance in app??, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/249179/glance-in-app) vs [Why does widget glance view never update?, forum, SDK 4.0.7 era](https://forums.garmin.com/developer/connect-iq/f/discussion/282931/why-does-widget-glance-view-never-update); SDK doc: `doc/Toybox/Application/AppBase.html`, `WatchUi/GlanceViewDelegate.html`.
- BLE apps: v7.1.0 fixed "crash caused by apps using BluetoothLowEnergy when rendering their glance view" and crashes when launching from a glance then continuing BLE. HeroSet does not use BLE; noted as an example that glance/launch interplay has had platform crashes. — SDK doc: `History.html`

- Live vs background glance updates (`simulator.json` -> `glance.liveUpdates`) for the 80 HeroSet products: **`liveUpdates: false` on 11** (fenix6, fenix6s, marqadventurer, marqathlete, marqaviator, marqcaptain, marqcommander, marqdriver, marqexpedition, marqgolfer, enduro); `true` on the other 69. So only 11 products relaunch the whole app per glance refresh (where `onStart`/`onStop` run every time and `requestUpdate()` does nothing), and all 11 are also in the 32 KB / "Build as Widget" group. Glance content areas range from 140x79 (fr255s) to 359x130 (fenix9pro51mm); fr965 is 299x148. — local device files `~/Library/Application Support/Garmin/ConnectIQ/Devices/<id>/simulator.json` (primary, installed with SDK manager, 2026)
- Runtime-context check for what HeroSet's `onStart` calls: the SDK 9.2.0 API pages list "App Types and Runtime Contexts" for `Sensor` (includes Glance) and `ActivityRecording` (lists Background, Glance, Watch App), but the `Complications` module page and `Application.Storage` page carry **no runtime-context list**, so the docs neither confirm nor deny that `Complications.updateComplication` (called from `HeroSetApp.onStart`) is usable in the Glance process. — SDK doc: `doc/Toybox/Sensor.html`, `ActivityRecording.html`, `Complications.html`, `Application/Storage.html`. Forum evidence says Storage works in a glance ("accessing application storage and making web requests" — `Core_Topics/Glances.html`).

**Missing / blank / stale**
- On CIQ 4+ devices an app must override `getGlanceView()` to appear in the glance list: "In API level 4.0.0 and above, apps and widgets must implement a glance view to appear in the glance list" (before 4.0.0 a default name-only glance was used). If `getGlanceView()` returns null the app name is used as preview content. — SDK doc: `Core_Topics/Glances.html`; `Toybox/Application/AppBase.html`
- Real-world consequence: popular widgets ported to CIQ 4+ lacked a glance because devs did not know; reported as bug CIQQA-3061 (2025-03-22, status "Acknowledged", no Garmin reply visible). — [bug report, Garmin forum](https://forums.garmin.com/developer/connect-iq/i/bug-reports/when-app-type-is-widget-in-manifest-xml-and-getglanceview-is-not-overridden-compiler-should-automatically-provide-default-glance-view-for-ciq-4-devices-for-max-portability)
- Typo `getGlancelView()` grayed out "Glance Launch Mode" in simulator (fr955, SDK 8.3.0/8.4.0). — [Why is Glance Launch Mode always disabled in the simulator?, forum, ~early 2026](https://forums.garmin.com/developer/connect-iq/f/discussion/429138/why-is-glance-launch-mode-always-disabled-in-the-simulator)
- fēnix 6 (non-Pro) with SDK 8.1.1: `getGlanceView()` bypassed, `getInitialView()` run instead despite glance mode enabled; SDK 8.1.0 gave "ERROR: null"; SDK 7.4.3 fine; not seen on fēnix 6 Pro; status Acknowledged, 2025-04-17. HeroSet lists fenix6/6s. — [Issues with SDK 8.1.x and glance on Fenix 6, forum bug report](https://forums.garmin.com/developer/connect-iq/i/bug-reports/issues-with-sdk-8-1-x-and-glance-on-fenix-6)
- SDK 8.1.x simulator no longer launched Instinct-2-like widgets in glance mode (2025-03-22, CIQQA-3059); reporter says real devices are fine. — [Bug report, forum](https://forums.garmin.com/developer/connect-iq/i/bug-reports/bug-report-with-connect-iq-sdk-8-1-0-widget-builds-for-instinct-2-like-devices-are-no-longer-launched-in-glance-mode-in-simulator)
- SDK 8.3 broke `GlanceView` on macOS/simulator (crashes before `onUpdate`), reported 2025-09-25 (CIQQA-3571); community says fixed in 8.4.0; commenter: "prevents all developers using macOS to develop widgets". Local SDK is 9.2.0, so past this. — [forum bug report](https://forums.garmin.com/developer/connect-iq/i/bug-reports/glanceview-is-broken-in-connect-iq-sdk-8-3-at-least-on-macos)
- SDK release notes list: "Fix glance view not showing app name if `getGlanceView()` returns null" (v8.4.0); "Fix widget app types not launching in glance mode" (v8.2.0); "Call `AppBase.onStop()` for glances that do not support live updates" (v7.2.0); "Launch an app in normal mode instead of glance when calling `exitTo()`" (v6.2.0); "Fix glance views not displaying" (v4.2.0.beta2). — SDK doc: `Readme/History.html`
- Firmware-side blank render: on fēnix 8 (and earlier devices) a glance first shows a gray rectangle with its name for 1–2 s before content; a forum reply calls it long-standing device firmware behaviour ("first reported maybe 2 years back"); no workaround given. Not present in the simulator. — [Glance delay in first render on Fenix 8, forum, ~2025](https://forums.garmin.com/developer/connect-iq/f/discussion/413803/glance-delay-in-first-render-on-fenix-8)
- Older firmware bug: "Connect IQ glances not showing if multiple present" fixed in fēnix 7 firmware 8.37 (via search snippet; not opened). — [Notebookcheck search result](https://www.notebookcheck.net/Garmin-rolls-out-new-software-update-to-Fenix-7-series-with-numerous-bug-fixes.629285.0.html) (unverified)
- Reports of glance order resetting after Garmin Express/Connect sync on fēnix 7 (fw 15.77), 7 Pro (17.28), Enduro 2 (26.09), and removed stock-ticker glances reappearing; workaround: put glances in folders. — [the5krunner Fix Files, 2026-08-07](https://the5krunner.com/2026/08/07/10-the-deep-dive-fix-files-week-ending-7-august-2026/) (secondary aggregator of user reports; Garmin has not confirmed a fix in what I saw)
- On glance-supporting fēnix 7 (touch), a widget opened from a glance did not close on right-swipe until the dev handled swipe manually (~2022). Note the SDK v7.2.0 later says it now "sends `KEY_ESC` on a right swipe" in the simulator to match devices. — [Fenix 7 custom widgets, glance view, swipe not working, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/285382/fenix-7-custom-widgets-glance-view-swipe-not-working-to-close-the-full-view-of-the-widget); SDK doc: `History.html`
- Time/timezone: I found no glance-specific timezone report. General platform issues exist: `Gregorian.info()` DST handling for non-today dates differs simulator vs device; `ActivityMonitor.History.startOfDay` timezone offsets. — [Gregorian.info() handles DST incorrectly..., forum bug](https://forums.garmin.com/developer/connect-iq/i/bug-reports/gregorian-info-handles-dst-incorrectly-for-dates-other-than-now-today-works-in-sim-not-on-device); [ActivityMonitor.History.startOfDay and time zones, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/944/activitymonitor-history-startofday-and-time-zones) (search-result paraphrase, not opened)

### Inferences
- HeroSet's `HeroSetApp.initialize()` allocates `HeroSetStore` and `HeroSetSyncCoordinator`, and `onStart()` runs `ensureCurrentDay()` and publishes a complication. Because `AppBase` and `onStart` run in the glance process (SDK lifecycle above), adding `getGlanceView()` means all of that either has to be `(:glance)`-safe and fit the cap, or be guarded (e.g. skip in glance context). Referencing any non-`(:glance)` type there is the Symbol-not-found / "Illegal Access" failure pattern reported above. This is inference from doc + forum evidence; the exact behaviour of HeroSet's store code in a glance has not been tested.
- The 1.0.0 crash class (watchdog on a real FR965 that the simulator under-measured) is the same shape as the 2019 memory restart loop: hard limits enforced only on device. A glance release should have on-device proof on at least one 64 KB-glance product and, ideally, one 32 KB product before shipping; the Device Reference table above shows where the caps differ.
- Stale-data risk: on non-live-update devices the glance is rendered by a fresh app launch at most every ~30 s and cached (SDK doc). A "today's progress" glance therefore must compute the current day itself rather than assume `ensureCurrentDay` already ran (already noted in `HeroSet/docs/ideas.md` risks).

### Gaps
- I found no first-hand report of glance behaviour across midnight/timezone change. Nothing glance-specific on `Time`/`Gregorian` in a glance context.
- I could not verify whether `getGlanceView` on `watch-app` builds for the 17 "Build as Widget" products is silently ignored or a build warning (the Device Reference note implies it is not supported; no forum thread confirms for a watch-app build). Needs a `monkeyc` test build for `fenix6` with a glance added.
- No verified real-device report of the "Illegal Access/Symbol not found" specifically from referencing a non-glance class inside `AppBase.initialize()`; the evidence is the Rez-in-class-var case and general statements.
- Storage read failures when the app and its glance run at the same time: no direct evidence found (only the single unconfirmed "competing applications" anecdote above). Whether `Complications.updateComplication` is legal from the glance process is not documented (see runtime-context finding); it needs a device or simulator test with `getGlanceView()` added.

## Q2. Effect on the listing, review and users; launch behaviour of `getInitialView`

### Takeaway
No source shows that adding a glance changes store review, adds a permission, or shows a "glance" badge in the store. The launch model does change: on CIQ 4+ products the same watch-app can be started from the glance list (with `:launchedFromGlance` in `onStart` state) or the app list, both calling `getInitialView()`; an app started from the glance loop is reported (by forum users, not Garmin docs) to be subject to widget-style timeout and no activity recording. Devices in HeroSet's list that cannot get a watch-app glance (32 KB / "Build as Widget") see no change.

### Cited Findings
- No permission is tied to glances: the glance API (`getGlanceView`, `GlanceView`) has no `uses-permission` requirement in the docs; the App Review Guidelines overview mentions widgets only as an app category and has no glance section. — SDK doc: `doc/docs/Readme` / `App_Review_Guidelines/Overview.html` (I grepped: only one "widget" mention), `Toybox/WatchUi/GlanceView.html`
- `AppBase.onStart(state)` gets `:launchedFromGlance` = true "if the app is started from glance list as opposed to the app list" (added in v4.0.0). — SDK doc: `Toybox/Application/AppBase.html`; `History.html` v4.0.0
- Forum: check `:launchedFromGlance` in `onStart`, not `DeviceSettings.isGlanceModeEnabled`, which only says glance mode is enabled on the device, particularly on "super-app" devices (e.g. FR265) that can start from either place. — [is there a way to check if an app was started by the glance view?, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/361081/is-there-a-way-to-check-if-an-app-was-started-by-the-glance-view)
- "Glances in watch-app types" support was added in CIQ 4.0.0 (simulator note); on CIQ 4+, forum consensus: the widget app type no longer exists and "any device app can implement a glance view via `getGlanceView()`"; apps started from the glance loop "time out after a certain period of inactivity and cannot record an activity" (flowstate, community user), while another poster says Edge devices don't time out. — SDK doc: `History.html` v4.0.0; [Glances and Widgets: User Input?, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/401977/glances-and-widgets-user-input). The official Connect IQ Basics doc says of the widget type that widgets "time out after a period of inactivity and are not allowed to record activit[ies]" — SDK doc: `Connect_IQ_Basics/App_Types.html`. The official doc does not spell out the glance-launched device-app case (unverified for CIQ 4+).
- A related bug: on fēnix 7/epix 2 (fw 9.33–10.44, reported 2022-12-14, "Acknowledged"), leaving an activity app to the watch face/glance carousel makes the activity stop and save; no developer-visible signal. — [forum bug report](https://forums.garmin.com/developer/connect-iq/i/bug-reports/bug-if-user-goes-to-watch-face-glance-carousel-from-activity-app-the-app-exits-session-is-saved-etc)
- Widget-only quirk: when launched from a glance the base view "doesn't have the input restrictions regularly applied" (glance mode passes up/down to the widget base page). For watch-app builds on CIQ 4+ there is no carousel, so this applies mainly to older widget builds. — SDK doc: `Connect_IQ_Basics/App_Types.html`, `DeviceSettings.html` (`isGlanceModeEnabled`)
- `System.exit()` from a glance-launched widget enabled from v4.0.6; `exitTo()` launches in normal mode (v6.2.0). — SDK doc: `History.html`
- Old forum behaviour when installing an app with a glance: the glance appears in the regular glance list by default; users can then move it into folders. Folder previews only show data if the app publishes a complication with `glancePreview="true"` (≈6 characters). — [Glance Folders and Complications, forum, ~2023](https://forums.garmin.com/developer/connect-iq/f/discussion/326713/glance-folders-and-complications)
- Users on fēnix 7/8-class watches see only glances (no full-screen widget loop); apps built as widgets appear as device apps and stay out of the glance list unless the developer added a glance. — [Activities & apps not showing... Fenix 8, forum](https://forums.garmin.com/apps-software/mobile-apps-web/f/garmin-connect-mobile-ios/391805/activities-apps-not-showing-on-connect-iq-app-under-devices-for-fenix-8) (~2025); [Glances and Widgets: User Input?, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/401977/glances-and-widgets-user-input)
- FR970 manual: swipe up from the watch face to scroll the glance list; "Device apps: add interactive features ... such as glances". — [FR970 Owner's Manual, Connect IQ features (Garmin)](https://www8.garmin.com/manuals/webhelp/GUID-025D75CF-3445-49E1-8D81-1AA74AB4E00F/EN-US/GUID-A220800C-E71B-40EC-B1D2-D3BCFB50EFCB.html)
- Store/process context (2025–26), not glance-specific: paid apps were hidden from the store on 2025-02-17 pending Trader Verification (already passed for HeroSet since it is live); 2025-11-20 the mobile Connect IQ Store app became the sole place to buy/install/manage apps, developer dashboard moved to apps-developer.garmin.com. — [Garmin dev forum announcements list](https://forums.garmin.com/developer/connect-iq/b/news-announcements); [Changes to the Connect IQ Store, 2025-11-20](https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/changes-to-the-connect-iq-store)
- User-reported (single forum thread, contested date, no Garmin confirmation seen): CIQ apps installed/updated in 2026 stop working after ~39–40 days without a Garmin Connect connection. If true it would apply to a new HeroSet version regardless of glance. — [FYI: CIQ apps installed in 2026 will stop working... , fēnix 7 forum](https://forums.garmin.com/outdoor-recreation/outdoor-recreation/f/fenix-7-series/436352/fyi-ciq-apps-installed-in-2026-will-stop-working-if-unit-is-not-connected-to-gc-39days/2040517) (unverified user report; thread page said "4 months ago", i.e. roughly mid-2026; Garmin staff only said they would follow up)
- Regression on non-glance devices: the only mechanism found is the memory point (`:glance`-annotated code is not compiled out for non-glance devices, per a 2019 forum statement) and the `AppBase`-always-loaded rule. No source reports user-visible regressions on non-glance devices. — [Memory usage by "Code" in Glance View, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/195448/memory-usage-by-code-in-glance-view)

### Inferences
- HeroSet's main view starts the accelerometer via the `Sensor` permission and, in the dev build, records an activity. If a glance click starts `getInitialView()` under widget-like restrictions on a given firmware, the workout screen could be launched with different lifecycle rules than from the app list. That is unverified for CIQ 4+ device apps; it needs a device test (launch from glance, do a set, back out) on the FR965. Detect with `:launchedFromGlance` if behaviour differs.
- No evidence the store review treats a glance differently; the manifest change is purely code (no new permission line), so a "full review cycle" is expected anyway for any new upload per the repo's own ADR-047 wording. The store form's What's New and CHANGELOG entry are the only listing-side changes required.
- Sequencing risk with 1.2.0 Connect sync (ADR-043, `ActivityRecording` session, ADR-047): forum evidence says a device app started from the glance loop cannot record an activity, and ADR-043 already notes `onStop` does not run after a crash. Shipping a glance before or with sync creates a new entry path (glance -> app) where a session start might be refused or behave differently. Add a device test "launch from glance -> set with Connect Sync on -> save" and consider guarding session start on `:launchedFromGlance`. Inference only; not confirmed for CIQ 4+.
- 17 of the 80 products (fēnix 6 family, marq gen 1, Descent Mk2, FR945 LTE, Enduro) will likely see no glance from a watch-app build. The listing should not promise a glance on all 80 products (matches ideas.md "sweep into compatibility.md before claiming it").

### Gaps
- No source states whether the Connect IQ Store/GCM displays glance support for a listing (I found none; listing pages surfaced were unrelated watch faces named "Glance").
- No first-hand report of a paid app's review time or rejection changing after adding a glance.
- Behaviour of `getInitialView` timeouts/activity recording for a CIQ 4+ device app started from the glance list is only forum-asserted.
- Whether an existing installed watch-app auto-appears in the glance list after an update (versus needing the user to add it) is not directly documented for CIQ 4+; the ~2023 forum answer says glances appear in the list by default on install. Update behaviour: no source.
- "Glance disappearing after app update": no direct report found. Closest: glance order/reappearing-glance bugs on sync (2026) and SDK-regression threads.

## Q3. Firmware/SDK 2024–2026: are glances still first-class?

### Takeaway
Yes. Nothing found deprecates glances or `GlanceView`; SDK 9.2.0 (2026-06-09) docs still describe glances as a supported API (3.1.0+), and glance-related fixes continued through 8.x and 9.2.0. "Widget" as an app type is effectively folded into device apps on CIQ 4+, and glance support is required to appear in the glance list.

### Cited Findings
- SDK 9.2.0 release (2026-06-09): bug fixes, Sleep Score complication, bonded BLE connections; compiler notes include glance-related fixes (barrel resources, `(:glance)` without `getGlanceView`). — [Connect IQ SDK 9.2 Now Available](https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/connect-iq-sdk-9-2-now-available); SDK doc: `Readme/History.html`
- SDK timeline (Garmin news list): 8.1.0 (2025-03-04, "System 8": VS Code extension, extended code space paged in on demand up to 16 MB on compatible devices, notifications API); vívoactive 6 (2025-04-01); 8.2 (2025-06-19); 8.3 (2025-09-25); 9.2 (2026-06-09); fēnix 9 / 9 Pro added to SDK manager (2026-08-25). None of the summaries mention glance deprecation or renaming. — [Connect IQ News & Announcements](https://forums.garmin.com/developer/connect-iq/b/news-announcements); [SDK 8.1.0 post](https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/connect-iq-sdk-8-1-0-now-available)

### Inferences
- Glances are the only supported "at a glance" surface for device apps on CIQ 4+; HeroSet's target of watch-app + glance is the sanctioned pattern. No deprecation risk visible within the 2026 SDK docs.

## Q4. Alternatives and complements for a daily-goal habit app

### Takeaway
A glance is a low-risk complement to the ADR-044 complication, not a replacement: complications feed watch faces (and glance-folder previews), a glance serves the glance list, and full-screen widgets no longer exist on CIQ 4+ (the full app is the "widget"). Evidence for "Controls"/smart-notification alternatives is thin.

### Cited Findings
- Complications publish/subscribe (CIQ 4.2+); a device app publishes and watch faces subscribe; `glancePreview="true"` on a complication drives the glance-folder preview text. — [Glance Folders and Complications, forum](https://forums.garmin.com/developer/connect-iq/f/discussion/326713/glance-folders-and-complications); repo `HeroSet/docs/decisions.md` ADR-044
- `ComplicationPublisher` permission is invalid for a `widget` app type, so "one widget for older glances + complications" isn't possible; an older thread confirms the developer had to consider separate apps. (Old, beta-era; HeroSet is a watch-app so unaffected.) — [Glance views from widget vs watch-app, forum, ~2023](https://forums.garmin.com/developer/connect-iq/f/discussion/319188/glance-views-from-widget-vs-watch-app)
- SDK 8.1.0 introduced a notifications API for delivering info from background; SDK doc has a "Notifications" core topic. — [SDK 8.1.0 post](https://forums.garmin.com/developer/connect-iq/b/news-announcements/posts/connect-iq-sdk-8-1-0-now-available)
- Data fields are for in-activity display and have their own memory limits (fr965 256 KB). — SDK doc: `Device_Reference/fr965.html`

### Inferences (comparison table, my synthesis)

| Option | Surface | Data freshness | Memory/risk | Fit for daily-goal check |
|---|---|---|---|---|
| Glance (getGlanceView) | Glance list on CIQ 3.x widgets/CIQ 4+ apps | Rendered on system schedule, cached on low-RAM devices | 64 KB (53 products) / 32 KB widget-only (17); crash risk if scope wrong | Best for "am I done today" from the glance list |
| Complication (ADR-044, done) | Watch faces that subscribe (HeroFace only, private) + glance-folder preview text | Pushed by app on publish | Already shipped; CIQ 4.2+ | Best for the watch face, limited to one value |
| Full app / former "widget" view | App list / glance tap | Live | Existing | Already the dashboard; costs a launch |
| Data field | Inside activities only | Live during activity | 256 KB fr965 | Poor fit: HeroSet is not an activity |
| Notification / Controls | System notification | Push-like | Notifications API (SDK 8.1+) | Nudge, not a status view; not researched in depth |

### Gaps
- I did not find any documented "Controls" mechanism for third-party apps; not researched beyond this. Treat the Controls row as unverified.
- No user-preference evidence (reddit/r-garmin) comparing glance vs complication for habit apps; reddit searches returned nothing usable.

## Q5. Monetisation, listing tips, simulator screenshots

### Takeaway
No glance-specific monetisation or listing rule was found. Simulator glance capture works via the `Settings > Glance Launch Mode` setting (only enabled if `getGlanceView()` is overridden), and the simulator has been buggy for it in several SDK versions; treat screenshots as a manual step.

### Cited Findings
- Simulator: glance launch is controlled by `Settings > Glance Launch Mode` (renamed from "Glance View" in v4.1.4); it is grayed out if the app doesn't implement `getGlanceView()` (including via typo). Sim also "Add glance support for devices with subscreen support" and "Enable simulator support for glances on fr245/fr245m/fr945" (old). — SDK doc: `Readme/History.html`; [forum thread 429138](https://forums.garmin.com/developer/connect-iq/f/discussion/429138/why-is-glance-launch-mode-always-disabled-in-the-simulator)
- Simulator regressions for glances: 4.1.1/4.1.2 lost glance recognition (fēnix 6 Pro; `isGlanceModeEnabled` false); 8.1.x Instinct-2-like widgets not launching in glance mode; 8.3 macOS GlanceView crash (fixed 8.4.0 per community). — [forum thread 292505](https://forums.garmin.com/developer/connect-iq/f/discussion/292505/glance-view-with-ciq-4-1-x-simulator); [bug 8.1.0](https://forums.garmin.com/developer/connect-iq/i/bug-reports/bug-report-with-connect-iq-sdk-8-1-0-widget-builds-for-instinct-2-like-devices-are-no-longer-launched-in-glance-mode-in-simulator); [bug 8.3](https://forums.garmin.com/developer/connect-iq/i/bug-reports/glanceview-is-broken-in-connect-iq-sdk-8-3-at-least-on-macos)
- Simulator has "File > Save Screenshot" (secondary search-result claim; not verified on 9.2.0). — [search result: forum thread 292505 context](https://forums.garmin.com/developer/connect-iq/f/discussion/292505/glance-view-with-ciq-4-1-x-simulator) (unverified)
- Monetisation/store rules are in the SDK docs (`Monetization/*.html`, `App_Review_Guidelines/Overview.html`); neither mentions glances (grepped). Store process changes noted in Q2.

### Inferences
- A glance screenshot for the listing is best produced from the simulator on fr965 with Glance Launch Mode on; the existing `HeroSet/listing/src/*-window.png` workflow (from git status: `fr965-*-window.png`) suggests window captures are already used, so the same could work for the glance. Verify in the simulator before promising it in the listing plan.
- A glance is a retention/visibility feature, not a monetisation mechanism; no evidence it changes conversion.

### Gaps
- No source on whether store listing screenshots may show a glance or on category effects.
- No data on paid-app conversion or reviews mentioning glances.
- Screenshot method for glance mode not verified on SDK 9.2.0.
