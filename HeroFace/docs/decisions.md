## ADR-001: Free + Pro ladder

**Status: Accepted (Active) 2026-10-04: the owner approved the Free + Pro ladder on 2026-10-04 (OD1 and OD2 in `../../reports/Free and Pro ladder.md`).** Written 2026-10-01 as Proposed. Ladder replaces plan.md decision 8 (paid at lowest tier, USD 2.00, one price for the one app); day-45 price-flip rule retired. Pro price **decided by ADR-004 (price: the $2.50 tier for every paid app)**; still owner's, not decided here: icons, translations, every upload. Nothing here uploaded or priced.

**Decision.** HeroFace ships as pair built from one codebase at compile time, method DaysToGo and DayArc use (`../../DaysToGo/docs/decisions.md`, ADR-014 there, and `../../DayArc/docs/decisions.md`, ADR-003 there: no runtime toggle, no unlock key, no locked items):

- **Pro** = existing app: `manifest.xml`, live app id `8cd8f7f5-2169-42a6-b6c2-c1e797e2f313` (never changes), `monkey.jungle`, excludes every `(:free)` symbol, uses `resources;resources-pro`. On-watch name "HeroFace Pro" (placeholder: owner names it). Version 1.1.0 (UNRELEASED). **Behaviour intended identical to 1.0.1** (simulator suite passes: 24 tests on fr965, fenix5s, fr55, 2026-10-01; not checked on a wrist): same seven settings, ids, defaults; `resources-pro/settings` byte-identical to old `resources/settings` apart from properties file's comment line.
- **Free** is new: `manifest.free.xml`, app id `be68898f-995b-45d9-860e-42ad508bd7fd` (generated with `uuidgen` 2026-10-01, never changes once published), `monkey.free.jungle`, excludes every `(:pro)` symbol, uses `resources;resources-free`. On-watch name "HeroFace" (placeholder). Version 1.0.0 (UNRELEASED). Same 117 products, same `minApiLevel` 3.0.0, same 15 languages, same single permission as Pro, `ComplicationSubscriber`. Free's permissions subset of Pro's, here means equal: HeroSet mode is point of Free (funnel to HeroSet, plan WP6), needs permission, so Free cannot have fewer.
- **The split** (plan WP6 step 1). Free: Everyday mode and HeroSet mode (Mode setting, Auto or Everyday), slots fixed to Auto, Accent ids 0 to 2. Pro adds: metric per slot (Slot1 to Slot3), Seconds, Weather (temperature). Pro-only feature needing API Free does not need not compiled into Free, so Free has no `Toybox.Weather` reads, no partial-update path.
- **Free shows no temperature, no seconds.** Temperature sits in row under time beside streak; in Free row carries streak alone, centred, which layout already did whenever temperature off. Seconds drawn beside time; in Free that box never drawn.
- **Accents: HeroFace keeps shipped three in both tiers (Blue 0, Cyan 1, Magenta 2); no colour added.** Plan contradicts itself. WP1 says HeroFace "stays at its shipped three unless the daring pass re-cuts its role palette or track", gives no ids above 2; WP6 step 1 lists Free accents "{0,3,4,5,6,7}", Pro "0 to 11", "alternate layout". WP6 line = DaysToGo's id table pasted in (ids 3 to 7 are Pink, Violet, White, Cyan, Lime there; White and Lime collide with HeroFace's reserved white and green; table gives HeroFace no id 3 or above), so outdated; this ADR follows WP1. Free and Pro offer same three. Alternate layout does not exist, not built (no redesign). Both owner's to settle, with daring pass.
- **Magenta missed track rule: resolved 2026-10-04 by ADR-003.** Shipped Magenta measured 2.84:1 against TRACK, under face's own rule of 3:1. Owner chose to recolour id 2 (same id, same name), so Magenta now `#FFAAFF` at 4.42:1; see ADR-003. (As first written, entry left it open and `magentaMissesTheTrackRuleKnownIssue` pinned failing figure.)
- **Settings files live only in tier folders**: `resources-pro/settings/` (every key) and `resources-free/settings/` (Mode and Accent). Shared `resources/` holds no settings file, so two never overlap, compiler never asked which wins. HeroFace has no generator, two lists short, both written by hand; `tools/check_free_package.sh` fails if Free's Mode or Accent list differs from Pro's, the drift check a generator would give.
- **AppName** lives only in `resources-pro/strings` and `resources-free/strings`, not in `resources/`, not in the 14 `resources-<lang>/` folders: language folder defining it would override tier name on non-English watch. Language does not inherit default's strings (compiler warns "String id 'AppName' undefined for language ..."), so each jungle also appends its tier folder to every `base.lang.<l>` path. `tools/check_strings.py` enforces both rules.
- **Code** (all behind `(:pro)` / `(:free)` twins, Free twin returning default): `HeroFaceSettings` reads Slot1 to Slot3, Seconds, Weather only in Pro (Free: Auto slots, no seconds, no temperature, no key requested); `HeroFaceReadings.temperature` (Weather reads); `HeroFaceView.onPartialUpdate`, `disableSeconds`, seconds-box field, `HeroFaceDelegate.onPowerBudgetExceeded`; constants `SETTING_SLOTS`, `SETTING_SECONDS`, `SETTING_WEATHER`. Leaving `onPartialUpdate` out of Free matters beyond size: SDK 9.2.0 `WatchUi.WatchFace` reference says it "is called each second as long as the device power budget is not exceeded", so face defining it called every second in low power; Free face with no seconds should not be. Not removed from Free: unreferenced display strings of Pro settings (`setting_slot1`, `metric_*`, `setting_seconds`, `setting_weather`, shared with Pro, every language) and seconds drawing in `HeroFaceClock`, which only runs when state carries seconds, so dead in Free; cutting it would fork shared drawing and screen-fit test's widest states. Free build's settings, properties, on-watch name, compiled code carry no "Pro" word, no Pro key; no locked or greyed item, no upgrade text.
- **Properties missing-key behaviour.** SDK 9.2.0 reference (`doc/Toybox/Application/Properties.html`) says `Application.Properties.getValue` throws `Properties.InvalidKeyException` for key absent from properties file. Free never calls it for Pro keys, so nothing depends on it; `HeroFaceSettings.read` already catches exception. `freeMissingPropertyKeyThrows` records what simulator does: passed on Free jungle (fr965, fenix5s, fr55, 2026-10-01), so simulator throws `InvalidKeyException` for missing key (not null, not a default). Says nothing about real watch.
- **HeroSet link unchanged.** One private complication, field order fixed by [ADR-044](../../HeroSet/docs/decisions.md#adr-044) (the complication contract), same parser, same label, same `ComplicationSubscriber`. Nothing in `HeroFaceLink`, `HeroFaceContract` or HeroSet changes, so nothing in HeroSet's ADR-044 changes. **Open, owner and device:** link is private, restricted to apps signed with same developer key; Free app has new app id, signed with same key. That it connects from Free app id not proven (simulator only, if at all); needs two apps on a watch.
- **Store text.** Free description says in one line HeroSet mode needs HeroSet installed (`listing-free/paste.md`). Existing `listing/` not changed: listing-repair submission pending.
- **Verification** (`docs/development.md`, "Checking a store package"): `tools/check_free_package.sh` unpacks compiled `.iq` packages, fails if Free settings contain Pro key, if "Pro" appears anywhere in Free package, or if Pro package lacks them; `tools/compile_sweep.sh` compiles every product for both jungles; `tools/run_tests.sh <device> [jungle]` runs suite on either.

**Why.** Plan WP6 (`../../reports/Free and Pro ladder execution plan.md`): free twin reaches watches paid listing cannot (Garmin sells paid apps only on its own list), is funnel to HeroSet, owner asked for missing Free/Pro variants. Compile-time split keeps one source, no licence server, no locked UI.

**Consequences.** Existing paid users lose nothing: Pro keeps every setting and behaviour of 1.0.1. Free = new, smaller app (no temperature, slots always Auto, no seconds). Live paid app's on-watch name becomes "HeroFace Pro" at 1.1.0: visible change for existing buyers, owner's call; plan folds store rename into pending listing-repair submission. Pro headline thin: three bars' metrics, seconds, temperature are whole difference, because daring pass and extra accents not built. Typed-code cleanups needed to meet strict compile (`-w --typecheck 3`) with no behaviour change: four casts or local variables in `HeroFaceLink`, `HeroFaceSettings`, `HeroFaceStreak`, same in three tests; project only ever built at default check level. **Owner decisions, not made here:** store names and titles, Pro price, icons, translations of any new string, uploads (Free 1.0.0 as new app, Pro 1.1.0 on existing id, together), site deploy, Magenta decision above, third accent and alternate layout, OD1 to OD4.

## ADR-002: Instinct family: window gauge, black and white, no accent
**Status: Accepted (Active) 2026-10-04 (owner approved the ladder 2026-10-04). Written 2026-10-03 as Proposed; the owner approved the look (mockup `docs/archive/instinct-mockup.html`) the same day and chose to hide the Accent setting on these watches. Nothing has run on a watch (the owner has none): simulator evidence only. Not uploaded. Accepted does not mean device-proven.**

**Context.** `plan.md` listed Instinct semi-octagon family as "phase 4, taken up only if the reviews ask". Owner asked 2026-10-03. Seven products: `instinct2`, `instinct2s`, `instinct2x`, `descentg1` (CIQ 3.4), `instincte40mm`, `instincte45mm`, `instinct3solar45mm` (CIQ 6.0). `instinctcrossover` left out as in HeroSet ADR-055 (its analog hands cover display; simulator shows no window). 1-bit (palette `000000`/`FFFFFF` only), 176 x 176 (E 40 mm 166 x 166, 2S 163 x 156), round **window** (62 px, 52 px on E 40 mm, 54 px on 2S) cut into top-right corner. **Watch-face memory 65,536 B** (ADR-001's 96 KB floor does not hold).

**Decision.**
- **Products.** The 7 join both manifests (124 products each tier), one build per tier. At or above `minApiLevel` 3.0.0.
- **Layout.** `HeroFaceLayout` asks `WatchUi.getSubscreen()` on `SCREEN_SHAPE_SEMI_OCTAGON` products only, so no round product's geometry depends on it. Rows are boxes: side margin each side; row starting above window's lower edge plus ring clearance ends left of it, centred in remaining band (`rowCenterX`). **Bezel ring becomes gauge in window** (hairline circle, thick fill from 12 o'clock, closed when every goal done; other ring never closes). As built: time (largest of `FONT_NUMBER_HOT`/`MEDIUM` fitting band, 44 px on 176 px screen) and date share band left of window, streak just below window, three mission columns (value, bar, label) end above bottom corners.
- **Not drawn on an Instinct.** Footer (battery, heart rate, notifications), temperature, seconds: watch's smallest font 23 px tall on 176 px screen (20 px on 166), no room. Mockup (`docs/instinct-mockup.html`, drawn with 15 px type) showed footer and bigger time; real face = layout above.
- **Visible area is a circle (found by simulator screenshot, 2026-10-03).** Bezel hides corners: visible = square cut by circle about 98 px radius (96 to 100 px, from alpha mask of SDK's device images, all seven products). `HeroFaceLayout` clips every row's insets to 96 px circle (`VISIBLE_RADIUS_PX`); fit test fails any text box whose corner leaves it (`collectCorners`; boxes include font padding, stricter than ink). First built layout had mission labels clipped by corners ("STEPS" lost its S); fix made columns narrower, labels use short forms.
- **Black and white by annotation.** `HeroFacePalette` = two classes same name, `(:color)` and `(:mono)`; jungles exclude `mono` for every product and `color` for 7 Instinct products. All roles white. Bar track = outline under solid fill; done = full bar plus drawn check (never green alone); low battery has its number. **Per-product `excludeAnnotations` line replaces base list**, so tier's own exclude restated (`free;color` in `monkey.jungle`, `pro;color` in `monkey.free.jungle`); writing `color` alone would silently break Free/Pro split.
- **Accent hidden on Instinct (owner, 2026-10-03).** Accent list = own settings file (`resources-accent-<tier>/settings/accent.xml`); Pro's Seconds and Weather moved to `resources-pro-tail/settings/tail.xml` so phone's order stays Mode, Slots, Accent, Seconds, Weather on every other product. Instinct `resourcePath` leaves accent folder out, so those watches show no Accent setting. Property stays in `properties.xml` (shipped key never changes), `HeroFacePalette.accent()` returns white. Second resource folder cannot remove a setting (compiler merges settings files); absent folder can.
- **HeroSet link.** Instinct 2 family (CIQ 3.4) has no Complications, so face stays in Everyday mode there (`Toybox has :Complications` false in simulator); Instinct E and Instinct 3 Solar (CIQ 6.0) can link to HeroSet, which now runs on them (HeroSet ADR-055). Complication field order (HeroSet ADR-044) untouched.

**Consequences.** Pro on Instinct has no seconds, no temperature, no footer; Free and Pro look same there. No round product's drawing changed: `rowCenterX` returns centre, insets unchanged without window (round control suites pass).

**Site.** `../site/src/apps/heroface/facts.ts` still says `watchCount = 117` and "Every round watch", true for live app. Nothing about Instinct on site until upload approved and store lists the watches; then gate copy behind flag as HeroSet does (`instinctLive`), update count.

**Amendment 2026-10-04 (owner's standing authorisation to redesign HeroFace UI/UX; ROADMAP 9.10).** On 176 px Instinct three columns about 42 px wide, "check + STEP" did not fit, so finished step goal read "✓ ST." (label cut with "."). On 1-bit display finished goal's label now **reversed**: black on white pill two pixels wider each side (`HeroFaceMissions.drawLabel`, `HeroFaceLayout.doneLabelPad`), no check, label never cut for check; full solid bar still says "done" there too. Colour products keep green check and label unchanged. Evidence: simulator screenshots of Free and Pro on `instinct2` and `instincte40mm` (12-day streak seeded through app's own streak code in private copy, because simulator's history rows did not apply: "13-DAY STREAK" and "12-DAY STREAK" drew whole). Simulator only, no watch.

**Verification.** See `docs/compatibility.md` "Instinct family". Simulator only.

## ADR-003: Magenta recoloured to pass the track rule
**Status: Accepted (Active) 2026-10-04. Owner decision 2026-10-04 (ROADMAP 5.3, built as 5.8): "fix the HeroFace Magenta accent colour so it passes 3:1."**

**Context.** Face's own accent rule: 3:1 against TRACK (`#555555`) so part-filled bar still reads. Blue (`#55AAFF`, 3.05) and Cyan (`#00FFFF`, 5.95) pass; Magenta (`#FF55FF`, id 2) measured 2.84, failed (ADR-001 recorded known issue).

**Decision.** Id 2 keeps id, place in list, name "Magenta" in every language; colour becomes `#FFAAFF`. Only 64-colour value still magenta clearing rule: every channel 00, 55, AA or FF, green must rise from 55 to AA to lift luminance above 0.372 (3:1 line against TRACK); `#FF00FF` 2.38, `#AA55FF` (violet) and `#FF55AA` (pink) lower still. Measured: `#FFAAFF` 4.42:1 on TRACK, 12.45:1 on black. Collides with no reserved role (gold `#FFAA00`, green `#00FF00`, alert red `#FF0000`, white `#FFFFFF`, MUTED `#AAAAAA`, TRACK; `noAccentIsAReservedRoleColour` passes). Price: pale magenta, closer to time's white (1.69:1 against white) than old (2.63). Ids stay append-only for everything else: Blue and Cyan never changed.

**Why recolour of shipped id, against append-only rule.** Rule exists so saved setting does not change meaning. Here meaning (Magenta) kept, only shade moves, by owner's explicit call; new id would leave two Magentas in list and phone's stored `2` on failing colour. Existing Pro users who chose Magenta see lighter shade after 1.1.0: visible change, listed in CHANGELOG.

**Verification.** `everyAccentClearsTheTrackRule` (all three), `magentaWasRecolouredToClearTheTrackRule` (pins 4.42), `shippedAccentIdsKeepTheirColours` (Blue, Cyan, new Magenta), full suite on fr965, fr255s, epix2, instincte40mm, instinct2, both tiers (Instinct has no Accent setting, draws white); simulator screenshot with Magenta selected. Simulator only; not looked at on a wrist.

## ADR-004: Price: the $2.50 tier for every paid app

**Status: Accepted 2026-10-04 (owner, chat).** Supersedes price of plan.md decision 8 (paid at lowest tier, USD 2.00; `archive/plan.md`), resolves "Pro price" left open by ADR-001 (the Free + Pro ladder).

**Decision.** HeroFace Pro (paid app, live app id `8cd8f7f5-2169-42a6-b6c2-c1e797e2f313`) moves to **USD 2.50 tier** of Garmin's price points (US $2.49, eurozone 2,99 EUR; measured table in `../../research_notes/Free and Pro ladder/garmin_rules.md`, source https://developer.garmin.com/connect-iq/monetization/price-points/). Every paid app in studio (HeroSet, HeroFace Pro, Days To Go Pro, Two Suns Pro, DayArc Pro) takes same tier. HeroFace (Free) stays free. Owner sets tier in upload form.

**Why.** Room for later discounts or rise: Garmin's tiers $2.00, then every $0.25, so $2.00 tier left no step down. Tier converts to different number in each store, so no number stated where reader sees it.

**No price number on site or in listing text.** Neither listing's Description or What's New, nor pages under `site/src/apps/heroface/`, state a price.

**Open risk.** Garmin documents that changing price of approved app can take it out of store for re-review (SDK `Monetization/App_Sales`); how it treats repricing to higher tier not confirmed. Ship change together with next version upload (Pro 1.1.0), re-reviewed anyway. Garmin email on repricing cancelled (owner, 2026-10-04, [`../../ROADMAP.md`](../../ROADMAP.md) 2.1); agent re-reads Garmin's published policies instead (`../../reports/Garmin policies and design guidelines.md`, running), so risk stays open until report answers it.

**Reversed by.** The owner.

## ADR-005: Rectangle family: the ring follows the screen's edges
**Status: Accepted 2026-10-08. Look approved by the owner 2026-10-08 from the simulator screenshots (`device-test/rect-review/after/`). Proposed 2026-10-05 (agent, on the owner's request to add the rectangular watches). Simulator only, nothing on a watch. The rectangle look needs the owner's look-approval before any upload.**

**Context.** `compatibility.md` left rectangles out: "the row stack assumes a round chord; a rectangle wants its own proportions" (`archive/plan.md` phase 4). Five products at or above `minApiLevel` 3.0.0: `venusq`, `venusqm` (240 x 240 LCD, CIQ 3.3.6; `venusq` has 96 KB watch-face budget), `venusq2`, `venusq2m` (320 x 360 AMOLED, CIQ 5.0), `venux1` (448 x 486 AMOLED, CIQ 6.0, glass rounded about 53 px at corners). With no code change round ring sat on inscribed circle, cut mission row on `venusq2` ("MOVE" under ring), time's box (81 px at `FONT_NUMBER_MILD`, smallest number font there) did not fit its 71 px band, so `everyStateFitsThisDisplay` failed there.

**Decision.**
- **Products.** The 5 join both manifests (129 products each tier, one build per tier, no per-device resources, no bitmaps).
- **Ring becomes frame** (`HeroFaceLayout.rectangle()`, `frameBox`, `frameFillFor`; `HeroFaceRing.frame`): open-bottom rounded rectangle, inset and as wide as round ring (a fifth and a sixth of inset), corner radius 1.5 insets (clears X1's rounded glass; corner, margin, time reworked in 2026-10-05 amendment below). Track runs up left side, over top, down right side; bottom edge = open gap where footer lives (Open Ring Rule's rectangular form). Fill measured along that path in pixels from lower end of left side, clockwise like round ring's 220° origin; any progress shows a pixel, full share fills whole path, never closes. Same colours and meaning: day as a whole (accent, green when full), or XP into rank in HeroSet mode (gold).
- **Rows fit inside frame** as round rows fit inside ring: half ring width plus half text margin in from its centreline, and inside rounded corner at all four corners (X1's glass rounded at bottom too). Replaces old constant "one inset" for non-round screens, which had no product until now. Top and bottom margins half an inset (no chord to clear); gives time its band on `venusq2`.
- **Time keeps room for Pro's seconds on a rectangle.** Wide band would otherwise take `FONT_NUMBER_THAI_HOT` on X1 with no room beside it; on rectangle time font chosen with seconds' width reserved both sides (time stays centred). Round products unchanged.
- **Unchanged:** round and Instinct paths (insets and ring code not reached on a rectangle), stack order, fonts, always-on time (still drifts on 3 x 3 grid on burn-in AMOLEDs), complication contract (HeroSet ADR-044, field order), Free + Pro split (ADR-001, the ladder).
- **HeroSet mode** needs `Toybox has :Complications`: true on `venusq2`, `venusq2m`, `venux1`; false on `venusq` and `venusqm` (CIQ 3.3), which stay in Everyday mode.
- **Paid vs free reach (ROADMAP 10.15 precedent, ADR-004 for the price).** Venu Sq 2, Sq 2 Music, Venu X1 on Garmin's App Sales list (API 5.0 and 6.0 tiers), sold in live paid listings of Two Suns Pro and DayArc Pro, so HeroFace Pro can be sold there. Venu Sq and Sq Music (CIQ 3.3.6) not on list (lowest tier API 3.4): both stay in both manifests, as Instinct 2 family did, only Free twin reaches them. No model names in listing text.

**Consequences.** Test counts up by one (`rectangleRingStaysOnTheDisplay`, which on a rectangle checks frame stays on display and its fill arithmetic, elsewhere only that product not a rectangle): Pro 26 and Free 26 on round and rectangle products, 22 each on an Instinct.

**Verification.** `docs/compatibility.md` "Rectangle family". Simulator only.

**Amendment 2026-10-05, completed 2026-10-06 with the owner's two decisions below (square design pass; the owner asked for real square designs and chose to approve the built simulator screenshots before any upload).** Still Proposed, simulator only. First build's screenshots showed small time with large empty band under it on `venux1` and `venusq2`, frame close to glass on `venux1`.
- **Time sized and placed by its digits' ink, not font box.** Number font's box about a third empty headroom and descent (digits fill 0.68 to 0.69 of ascent, measured on simulator screenshots of all three sizes, not on a watch; the one stated exception to DESIGN.md's Measure-Never-Guess Rule, since Dc has no glyph metrics; `HeroFaceFrame.DIGIT_HEIGHT_PERMILLE` 720, DayArc's figure). On `venusq2` 103 px band missed `FONT_NUMBER_MEDIUM`'s 105 px box, fell to `MILD` (41 px digits). Now largest number font whose ink leaves stack gap above and below it in band, and whose widest time fits frame, is taken: `venusq` `THAI_HOT` (39 px digits, was `HOT` 28), `venusq2` `HOT` (80, was `MILD` 41), `venux1` `THAI_HOT` (108, was `HOT` 86). Screen-fit test checks ink box for time on a rectangle.
- **Stack balanced.** Height time does not use shared evenly by gap above time, gap under it, gap above footer (missions and row under time move up together), so no hole under time.
- **Seconds' room reserved only while seconds drawn.** First build kept Pro's seconds' width free beside time on every rectangle, both tiers; Free has no seconds and paid for it. Now layout keeps two time fonts (`timeFont`, `secondsTimeFont`, same font on round and Instinct products), clock takes second only while seconds drawn: with seconds on, `venusq2` drops to `MEDIUM` and `venux1` to `HOT`, time staying centred (centring time and seconds as one group would not keep larger font either: 364 + about 40 px exceeds X1's 398), grows back once if watch cuts seconds for power budget. Stated exception to "don't shrink a font to make text fit"; owner can overrule in look-approval.
- **Frame clears glass with even margin.** Centreline sits quarter inset in (8 px of black between frame and glass at 448, was about 5), each corner quarter circle centred 1.5 insets in from both edges. Venu X1's glass corner measures about **68 px** off SDK's device skin (60, 24, 10 and 0 px in from side at 0, 16, 32 and 60 px down; "about 53 px" above was wrong), 1.55 insets, so frame runs nearly concentric with it, margin stays about even round corner. Venu Sq and Sq 2 skins almost square (about 7 px): there round corner is design's own, not glass constraint.
- **Fill keeps lower-left start (decision).** Studio rule for rectangles (track following screen, from top centre, clockwise, share = share of path's length) describes closed track. HeroFace's ring open by design (DESIGN.md, Open Ring Rule: footer lives in gap), round form starts at lower left (220°, HeroSet's XP ring). Started at top centre, open path would either split fill across footer gap (right side fills, then fill jumps to lower left) or have to close and take footer's room. So keeps round ring's origin and direction, takes from studio rule what applies to open track: clockwise, share = share of path's length. User owning round and square HeroFace reads same gesture on both.
- **Owner decision 1 (2026-10-06, taken on the coordinator's recommendation): keep the edge frame.** 2026-10-05 steering said square watches get real square designs, "not a round design inscribed in a circle or wrapped in a frame". Frame here = square form of HeroFace's own ring (open-bottom track following screen's edges, studio rule), not round ring in a box, rows take frame's full width. No frameless alternative needed.
- **Owner decision 2 (2026-10-06, same): MOVE leaves the day ring's score, on round and rectangle alike.** `HeroFaceReadings.dayScore` averaged every metric with a goal, quiet MOVE bar is full (shows activity left before watch's move alert), so ring read about a third done at zero activity wherever MOVE is a slot (Auto slots resolve to it on Venu Sq and Sq 2), and turned green ("everything done") beside MOVE bar `HeroFaceMetric.isDone` never calls done. Score now averages goal-bearing metrics other than MOVE; DESIGN.md's Bezel Ring says so. `ringAveragesTheDaysMissions` checks it (zero activity with quiet MOVE = empty ring; other goals met = full one; MOVE alone scores nothing). User-visible change on round watches too: ring fills more slowly early in day where MOVE is a slot.
- **Reviewer fixes, 2026-10-06 (shared with round).** Gold streak outranks temperature in row under time: too-wide group tries streak's shorter wordings still saying streak beside temperature, then drops temperature and takes longest streak wording fitting alone; HeroSet's rank-only line never used to keep temperature (`HeroFaceState.streakLastDropsStreak`). Before, Pro on Venu Sq 2 in Lithuanian showed `RANGAS 2  68°` where Free showed `RANGAS 2  SERIJA 3`. On rectangle done label too wide for its column with check drops check in every column of row (`HeroFaceMissions.checkCrowds`), so one state drawn one way; label still too wide cut with ".". Both rules pinned by `streakOutranksTemperatureAndDoneRowsMatch` (one more test per tier). X1's frame showed dark 1 px column at top-right join in 3x skin shot; each straight run now reaches one pixel into its corner (`HeroFaceRing.frame`), retaken skin shot continuous (simulator).
- **Code.** Rectangle geometry moved out of `HeroFaceLayout` into `HeroFaceFrame` (frame, its fill, row inset, stack, ink-based time font). Round and Instinct paths unchanged (no frame built there; their two time fonts same font). Test counts unchanged: `rectangleRingStaysOnTheDisplay` also checks corner's centre and time never smaller with seconds off.

## ADR-006: Always-on time is the studio's one always-on grey, `#5C5C5C`
**Status: Accepted 2026-10-08 (agent, under the owner's standing authority to take the recommended option; ROADMAP 13.25). Simulator only.**

**Context.** Always-on time was `#555555` (`HeroFacePalette.SLEEP_TEXT`, same hex as track), 2.82:1 against black: under studio's 3:1 bar for persistent or always-on colour. Two Suns already moved its always-on text to `#5C5C5C` (Two Suns ADR-027 (always-on text is a dim grey)); ROADMAP 13.25 asks for one always-on grey across studio.

**Decision.** `SLEEP_TEXT` is `#5C5C5C` on colour palette: 3.14:1 against black (WCAG formula, computed from hex values), relative luminance 0.107 against 0.091, about 18% more relative luminance per lit pixel (computed), still about a quarter of MUTED (`#AAAAAA`). Track stays `#555555`; two keys already separate roles, now separate values. Instinct palette's `SLEEP_TEXT` stays white, never drawn there. `#5C5C5C` not a 64-colour value. `HeroFaceSleep.draw` is its one user; `HeroFaceView.onUpdate` calls it only when watch asleep and reports `requiresBurnInProtection`: AMOLEDs and, in simulator, first-generation Venu Sq and Sq Music (16-bit LCD, SDK `compiler.json`; whether real watches report it unverified, `compatibility.md`). Every product drawing it is 16-bit (SDK `compiler.json`: AMOLEDs such as `fr965` and `venux1`, and `venusq` LCD), so screen stores about `#5A5D5A`, still about 3.1:1 (computed). 64-colour MIP screen not expected to report flag: Garmin's AMOLED FAQ ties burn-in protection to AMOLED products (DaysToGo ADR-007, amended 2026-10-04); not checked per product. `onPartialUpdate` (Pro's seconds) does not use it.

**Evidence.** Test `alwaysOnGreyReadsOnBlack` pins 3:1 bar (one more test per tier: Pro 28, Free 28, 24 each on an Instinct). Always-on frames and 24-hour heat map, simulator only, on `fr965` and `venux1` (`DESIGN.md` "Always-On Time"); suites on `fr965`, `venusq2`, `instincte40mm`, both tiers. `venusq` (LCD taking this path in simulator) not shot. Not measured: legibility outdoors and ghosting on a wrist (2026-09-21/22 FR965 night ran on `#555555`).

**Reversed by.** Always-on night on a wrist showing grey unreadable, or simulator heat map reporting burn-in: one constant, `SLEEP_TEXT`.
